:::foreword
Hard tags cut. Soft chips recede. The list stays the list; the filter is what moves.
:::

A filter on a website is usually a set of checkboxes that remove rows. That model assumes every cut is exact and reversible only by undoing the check. Soft judgment filters need a different surface: the row can dim before it disappears, a wrong hide can be put back, and a new rule can be typed in plain language instead of picked from a fixed list.

The catalog on this page is closed. Hard tags are exact DATA labels in code. Soft chips are typed Nouls: “about waiting”, “not a chatbot”, “has a prototype”. Each chip scores every row. Rows that fail recede, then hide past a floor. The judgment does not invent a new row. It only orders and cuts what is already there.

Typing a need into the chip field is how a new rule enters. The sentence becomes a Noul when confidence is high enough; otherwise the field stays quiet and no chip appears. That is the same silence contract as Find and FAQs: a weak match is not a confident wrong filter.

Shneiderman (1983) argued for interfaces where the object of interest stays visible and actions are incremental and reversible. Opacity as the first response, hide as the second, and an explicit put-back for a bad chip, keeps the catalog visible while the filter works. A results page that replaces the index would break that. The index is the result.

The relevance floor is a mixing desk over stored scores. Moving it does not call the model again. Search, when present, ranks; filters cut. Same list, two controls.

:::notes
Shneiderman, Ben. Direct Manipulation: A Step Beyond Programming Languages. IEEE Computer, 1983.
Hard tags are exact. Soft chips are judgments. A miss is silence, not a bogus first keep.
:::
